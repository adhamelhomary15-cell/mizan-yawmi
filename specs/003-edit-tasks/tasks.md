**Tests**: The spec does not ask for a test framework. The plan adds one dev-only script, `tools/check-edit.js` (research R9), because SC-002, SC-003 and SC-005 claim 100% of cases. Browser checks follow [quickstart.md](quickstart.md).

**Organization**: grouped by user story. Plan phases map as: plan 1 = Phase 2 here, plan 2 = Phases 3-5, plan 3 = Phase 6, plan 4 = Phase 7.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 (edit a task), US2 (due date effects), US3 (mistakes and undo), US4 (edit an appointment)
- Only `src/planner.html` is edited for the app. `index.html`, `sw.js`, `manifest.webmanifest` and icons are generated by `tools/build.py` and never edited by hand.
- Rules for every task: no code that sets, bulk-sets or clears `done`, `checks` or `modules` (Principle II); no network call; no owner-specific value in any tracked file (Principle VI). Run `node tools/check-private.js` before each commit.
- Each phase ends at a checkpoint and needs the owner's go-ahead (Principle I).

## Phase 2: Foundational (blocks all stories)

**Purpose**: the pure rules, the dev-only check, the shared form, and the record-only undo. Nothing is wired to the visible list yet except where stated, so app behavior is unchanged at the end of this phase.

- [x] T003 Add pure helpers in `src/planner.html`, next to the other data helpers and before `TasksView`, with no UI and no storage access:
  - `validateTaskFields({text, tag, due})` returns `{ok, error?, value?}`. `value.text` is trimmed and cut to 140 characters (task `text`: "required after trim; at most 140 characters"); `tag` must be a key of `TASK_TAGS`; `due` is `YYYY-MM-DD` or `''`. Errors: `اكتب نص المهمة.` for empty text, `اختار النوع.` for a tag not in `TASK_TAGS`.
  - `validateApptFields({label, day, time})` returns `{ok, error?, value?}`. `value.label` is trimmed and cut to 60 characters (appointment `label`: "required after trim; at most 60 characters"); `day` is a number in `WEEK_ORDER`; `time` is required `HH:MM`. Errors keep the existing wording: `اكتب اسم الميعاد.` and `اختار الساعة.`.
  - `applyEdit(list, id, patch, allowedKeys)` returns a new list in which only the record `id` changes, and only for keys in `allowedKeys` (tasks: `text`, `tag`, `due`; appointments: `label`, `day`, `time`). Any other key in `patch`, including `done`, `created`, `id`, is ignored. An unknown id returns the list unchanged.
  - `restoreFields(list, id, before, allowedKeys)` puts the old values back into the record `id` if it still exists, otherwise returns the list unchanged.
- [x] T004 [P] Create `tools/check-edit.js` (dev-only, Node, no dependencies), following the style of `tools/check-settings.js`: extract the helpers from `src/planner.html` between two stable markers, and run checks over many generated inputs. Required checks: (a) after `applyEdit` on a task, `done`, `created`, `id` and every other record are deep-equal to before, for done and open tasks (FR-004, FR-005, SC-002); (b) a patch containing `done`, `created`, `id` or `checks` changes nothing; (c) empty and whitespace-only text is rejected and the validator never returns a value (SC-003); (d) over-long text is cut to 140 and label to 60; (e) a tag not in `TASK_TAGS` is rejected; (f) `restoreFields` restores exactly the edited record and leaves other records, including ticks made after the edit, untouched, and is a no-op if the record was deleted (SC-005); (g) appointment edits keep `id`. Exit 0 on pass, 1 on failure. Add a `--self-test` mutation that proves the check fails when a helper is broken.
- [x] T005 Add a shared form component `ItemForm` in `src/planner.html` before `TasksView`, built from the existing add-task and add-appointment markup (same classes `form`, `form-row`, `field`, `form-err`; same `maxlength` 140 and 60; same select lists). Props: kind (`task` or `appt`), initial values, submit label, onSubmit(value), onCancel. It owns its draft state, validates with the T003 functions on submit, shows the message in a `form-err` with `role="alert"` and does not call onSubmit when invalid, moves focus to the first field on mount, and calls onCancel on Escape. Contract: [contracts/ui-contract.md](contracts/ui-contract.md).

Pass it to `TasksView` as a new prop. Do not change `act` or `remove` (research R2).

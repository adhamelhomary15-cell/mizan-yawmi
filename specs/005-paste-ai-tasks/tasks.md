# Tasks: Paste Tasks from Any AI in a Fixed Format

**Input**: Design documents from `specs/005-paste-ai-tasks/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/paste-format.md](contracts/paste-format.md), [quickstart.md](quickstart.md)

**Tests**: The spec does not ask for a test framework. The plan adds one dev-only script, `tools/check-paste.js` (research R11), because SC-002 to SC-004 claim 100% of cases. Browser checks follow [quickstart.md](quickstart.md).

**Organization**: grouped by user story. Plan phases map as: plan 1 = Phases 1-2 here, plan 2 = Phases 3-5, plan 3 = Phase 6.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 (split with any AI, paste, preview, confirm), US2 (lines the app cannot understand are reported), US3 (adding many is safe and reversible)
- Only `src/planner.html` is edited for the app. `index.html`, `sw.js`, `manifest.webmanifest` and icons are generated by `tools/build.py` and never edited by hand.
- Rules for every task: no code that sets, bulk-sets or clears `done`, `checks` or `modules` (Principle II; new tasks are created with `done: false`); no network call, no AI call, no clipboard read, nothing stored beyond the session (Principle III); no real person's schedule, course or place in any tracked file (Principle VI). Run `node tools/check-private.js` before each commit.
- Each phase ends at a checkpoint and needs the owner's go-ahead (Principle I).

## Phase 2: Foundational (blocks all stories)

**Purpose**: the pure rules and their check. Nothing is wired to a screen, so app behavior is unchanged at the end of this phase.

- [x] T003 Add the paste parser in a marked block (`// start of task paste` ... `// end of task paste`) in `src/planner.html`, right after the edit-rules block and before `TasksView`: `parseTaskLines(text, tags, existingTexts)` returning `{items, rejected, skipped, leftOut}` as in [data-model.md](data-model.md). Rules, from [contracts/paste-format.md](contracts/paste-format.md): read the text line by line; skip blank lines and lines that are only a code fence (three backticks, optional language word) and count them in `skipped`; strip one leading list marker (`-`, `*`, `•`, or a number followed by `.` or `)`, Latin or Arabic-Indic digits); at most 50 candidate lines are read, the rest counted in `leftOut`; split on `|`: no `|` gives `no-separator`, more than two `|` gives `too-many-separators`; fields are `type`, `text`, optional `due`; the type is matched against the ids of `tags` and then against the labels, case-insensitively after trimming, and an unknown or empty type gives a proposed task with `tag: ''` (never an error and never guessed); text trimmed must be "1 to 140 characters" (empty gives `empty-text`, longer gives `too-long` with the length, never cut); due must be empty or a real `YYYY-MM-DD` (else `bad-date`), checked with `validateTaskFields`; each proposed task carries `n`, `text`, `tag`, `due`, `dupe` (true when its text, trimmed, spaces collapsed, case-insensitive, equals an entry of `existingTexts` or an earlier proposed line) and `include` (`true`, but `false` when `dupe` or when `tag` is empty). Invariant: `items.length + rejected.length + leftOut` equals the number of candidate lines.
- [x] T004 Add `buildAiPrompt(tags, todayIso)` in the same marked block, returning the instruction text of [contracts/paste-format.md](contracts/paste-format.md): the format line, the user's types as `id (label)`, the rule that the text is under 140 characters and has no `|`, the date format with today's date, "no numbering, no headings, no explanation", two example lines using the first two type ids and a date seven days after `todayIso`, and the closing line where the user writes their big task. Egyptian Arabic; no personal data.
- [x] T005 Add `undoBatch(list, batch)` in the same marked block: returns a new list without every task whose `id` is in `batch` (an array of `{id, text, tag, due}`) **and** is still untouched, meaning `done` is `false` and `text`, `tag` and `due` equal the batch entry; every other record is returned as is. It must not mutate its input.
- [x] T006 [P] Create `tools/check-paste.js` (dev-only, Node, no dependencies), in the style of `tools/check-edit.js`: extract the edit-rules block and the paste block from `src/planner.html` and run, over made-up generic samples: (a) every valid shape (three fields, two fields, empty third field, label instead of id, extra spaces); (b) every wrapping variant (code fence with and without a language word, bullets, `1.`, `2)`, Arabic-Indic numbers, blank lines); (c) every rejection code with the line number kept; (d) unknown and empty type give a proposed task with `tag: ''` and `include: false`; (e) text of 140 characters is accepted and 141 is `too-long`, never cut; (f) the 50-line limit and `leftOut`; (g) duplicates against existing texts and earlier lines, `include: false`; (h) the account-for-every-line invariant on 300 generated inputs (SC-002); (i) no proposed task is ever `done` and no output has a `done` field set to true; (j) `buildAiPrompt` contains every type id, today's date and the format line, and no `{`/`undefined` leaks; (k) `undoBatch` removes untouched batch tasks, keeps a ticked or edited one, keeps all other records, and does not mutate (SC-004); (l) the paste block never mentions `checks`, `modules` or `.done =`. Exit 0 on pass, 1 on failure. Add `--self-test` with mutations that MUST be caught (limit changed, text cut instead of rejected, type guessed, fence not skipped, duplicate not marked, undo removing a ticked task, a line dropped silently).
- [x] T007 Run `node tools/check-paste.js`, `node tools/check-paste.js --self-test`, `node tools/check-edit.js`, `node tools/check-settings.js --self-test`, `node tools/check-anchors.js`, `node tools/check-private.js`. Build with `PYTHONUTF8=1 python tools/build.py`, `git checkout` the icon files if Pillow re-rendered them, and run `node tools/check-parity.js --old $TEMP/baseline-planner.html --new src/planner.html --settings $TEMP/example-main.json` expecting 0 differences (nothing is wired yet).

## Dependencies and Order

- Phase 1, then Phase 2 (blocks everything). In Phase 2: T003 first (the others use its result), then T004 and T005; T006 can run alongside T004 and T005 once T003 exists.
- Phase 3 (US1) needs Phase 2. It is the MVP: stop here and valid pasted lines already become tasks.
- Phase 4 (US2) needs Phase 3 (it extends the same preview).
- Phase 5 (US3) needs Phase 3 (it wraps the confirm step); T017 and T018 touch the preview, so run them after Phase 4 to avoid colliding edits.
- Phase 6 needs all stories. If US3 is cut, skip T016-T020 and the undo checks; the rest stands alone but a batch would then have no undo, so US3 is not optional in practice.

## Parallel Opportunities

- T006 (the script) alongside T004 and T005 after T003.
- T022 (docs) alongside T021 and T023.
- Everything else touches `src/planner.html`, so it runs in order.

## Implementation Strategy

1. **MVP**: Phases 1, 2 and 3. Copy the instruction, paste the answer, confirm: tasks added open.
2. Add Phase 4 so messy real answers are handled and nothing is lost.
3. Add Phase 5 so a mistaken batch can be undone and big pastes stay bounded.
4. Phase 6 verifies, documents, and hands the diff to the owner. Nothing is pushed without the owner's request.

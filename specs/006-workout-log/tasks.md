# Tasks: Workout Log (Strong-style)

**Input**: Design documents from `specs/006-workout-log/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/ui-contract.md](contracts/ui-contract.md), [quickstart.md](quickstart.md)

**Tests**: The spec does not ask for a test framework. The plan adds one dev-only script, `tools/check-workout.js` (research R12), because SC-002 and SC-005 claim 100% of cases over generated histories. Browser checks follow [quickstart.md](quickstart.md).

**Organization**: grouped by user story. Plan phases map as: plan 1 = Phase 2 here, plan 2 and 3 = Phases 3 and 4, plan 4 = Phase 5, plan 5 = Phase 6, plan 6 = Phase 7, plan 7 = Phase 8, plan 8 = Phase 9. **Cut points** (research R13): **A** after Phase 4, **B** after Phase 6, **C** after Phase 8; each is a mergeable state and its own branch and pull request from this folder.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 (log a workout), US2 (timers), US3 (history and records), US4 (exercise list), US5 (routines), US6 (fix mistakes)
- Only `src/planner.html` is edited for the app. `index.html`, `sw.js`, `manifest.webmanifest` and icons are generated by `tools/build.py` and never edited by hand.
- Rules for every task: workout data lives only under the key `mizan-workouts-v1`; no code in this feature reads or writes the progress store (`useStore`, `fall26-planner-v1`), `checks`, `modules`, tasks, appointments, the schedule, or settings (Principles II and III); a set is done only by the user's tap with valid numbers; no network call, no notification permission, no account; no real person's exercises, weights or routines in any tracked file (Principle VI). Run `node tools/check-private.js` **with the new files staged** before each commit (it only reads tracked and staged files) and commit only if it is clean.
- Each phase ends at a checkpoint and needs the owner's go-ahead (Principle I).
